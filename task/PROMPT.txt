开发一个完全离线的构建代理权限清单规划器，只处理团队提供的虚构能力标识、项目、角色和申报需求。它不连接真实构建代理，也不执行系统权限变更。使用 Windows 原生 Python 3.12、标准库和可选 SQLite。提供 solve、verify、rollout、status 四个命令。

输入为最多 24 个候选授权包。每个包给出适用项目和覆盖的精确能力对 (scope,capability)、维护成本及冲突包集合。项目声明必须覆盖的能力对和绝对禁止的能力对；包覆盖的禁用对不能分割剔除。依赖以任一候选前置包满足的列表表示，可存在多个前置条件。最终状态需满足所有依赖、冲突和必需能力。先最小化所有代理在终态获得但未申报的能力数，按 (project,scope,capability) 去重，再最小化总成本，最后以排序后授权包 ID 序列择先。旧策略可包含计划淘汰的包，输入声明当前正在运行的必保能力。过渡期间对每个项目都保持必保能力与禁用规则；每个步骤只能启用、停用一个包，或执行输入明确允许的一对原子替换。约束还包括每个过渡状态的包冲突与依赖。最终最优解必须存在从旧状态出发的合法路径；在同一最优解的合法路径中最少步数优先，再按公开规定的操作字典序择先。找不到时返回可独立复核的无可达目标结论，公开求解状态数，缓存已见状态，不能因探测上限返回最优。

verify 核对计划每一步及终态，判断终态全部约束。rollout 逐步骤验证当前代次和预期状态再写入模拟台账，为每步记录前后摘要和幂等键。重启后以已提交步进度接续；服务外的旧代计划、同 ID 异内容以及意外状态均拒绝继续。故障注入只使用自有进程正常退出或持久化前的受控异常。

交付 README、夹具、测试。包含终态静态最优但不可落地、只有原子替换才能通过、共享能力去重影响排名、依赖循环可在旧态已存在但无法单步新建、代次冲突与中途恢复。小实例用独立枚举校验目标和步数。
